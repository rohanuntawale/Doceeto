# Doceeto mobile app

`mobile/` is the Capacitor Android shell for the existing Next.js web app. The
APK loads the deployed Doceeto app directly, so the landing page, login,
patient signup, doctor signup, nurse signup, OAuth, and role-specific routes
remain the same source of truth as the web app.

## Development

```powershell
cd mobile
npm install
npm run dev
```

Open `http://localhost:5173` to work on the optional local mobile client. The
Android wrapper defaults to `https://doceeto.vercel.app`. Override the APK
origin only when testing a reachable local or staging Next.js server:

```text
CAPACITOR_SERVER_URL=https://your-staging-origin.example.com
```

For an Android emulator, the host machine is `http://10.0.2.2:3000`. For a
physical device, start the root app on all interfaces and use the computer's
LAN IP:

```powershell
cd ..
npm run dev -- -H 0.0.0.0
cd mobile
# mobile/.env: VITE_API_BASE_URL=http://192.168.x.x:3000
npm run dev -- --host 0.0.0.0
```

## Authentication

Because the APK keeps the deployed web origin, it uses the web app's normal
same-origin session cookies and OAuth callback. No mobile CORS bridge or
duplicate authentication flow is required.

## Android debug APK

Prerequisites:

- JDK 17
- Android Studio
- Android SDK Platform 36 and Build-Tools
- Android platform-tools (`adb`)
- A connected device with USB debugging, or an emulator

```powershell
cd mobile
npm install
npm run android:build
```

APK path:

```text
mobile/android/app/build/outputs/apk/debug/app-debug.apk
```

Install directly:

```powershell
adb install -r mobile/android/app/build/outputs/apk/debug/app-debug.apk
```

Or transfer the APK to the device and enable **Install unknown apps** for the
file manager used to open it.

Useful scripts:

```powershell
npm run cap:sync
npm run android:open
npm run android:build
npm run android:install
```

The Android project uses `health.doceeto.app`, `Doceeto`, `minSdkVersion 23`,
and the current target SDK generated by Capacitor. It declares `INTERNET` and
coarse/fine location because booking uses the browser geolocation API and
Capacitor maps its permission prompt to Android runtime permission. No camera,
microphone, notification, or storage permission is used by the five-screen
mobile client.

## Release later

A signed release would additionally need a private keystore, Gradle signing
configuration supplied through secure CI secrets, production versioning, and
release QA. None of those are included in this sideload-only debug build.
